# QA Checklist

## Must pass

- It's 16:9 horizontal.
- The background is clean white.
- Inky is present.
- Inky carries the core action, not just decoration.
- No cloned old-case composition — a fresh metaphor was generated for this article.
- The frame is whimsical, creative, interesting.
- Clean and sparse; subject under ~60% of the frame.
- One image tells one core structure.
- Labels are few, short, and readable.
- Orange is used only for the main path or arrows.
- Red is used only for key points, problems, warnings, or results.
- Blue is used only for supplementary notes, feedback, or system state.

## Failure signals

If any of these appear, regenerate or edit locally:

- A top-left title like "Common Pitfalls / Workflow / System Architecture / Roadmap."
- Inky looks like a mascot sticker, an emoji, or a cute cartoon.
- The frame reads like a PPT, course slide, or formal flowchart.
- Too many elements, too many arrows, too many nodes.
- Text has swollen into long paragraphs.
- The background has paper grain, shadow, gradient, beige, or noise.
- A realistic UI screenshot or techy interface.
- Bad typos or unreadable labels.
- The frame is stiff, with no absurd metaphor.
- Too similar to an old case in `assets/examples/`.

## Iteration methods

- Too plain: make Inky the action subject, add a strange-but-coherent metaphor.
- Too complex: cut nodes, keep one action and 3–5 short labels.
- Too cute: emphasize deadpan, blank serious expression, not cute, not a mascot.
- Too PPT: drop the title, borders, tidy grid, and excess arrows; switch to a hand-drawn scene.
- Too like an old case: keep the core meaning, swap the main object and Inky's action.
- Bad text: prefer a local edit; if there are many errors, regenerate with fewer labels.

## Delivery test

A high-quality image should make the reader first think "huh, that's a little weird," then understand the structure within 1 second.

If the first glance reads like a tutorial page instead of a whimsical product sketch on blank paper, it fails.
