# Copy Test (Harry Dry's 3 rules)

## Overview

A fast, mechanical test for whether a line of marketing copy is **unforgettable** or just filler. Run three questions on every sentence. Each fail is a "free no" - cut or rewrite it. Each pass is a "free yes" - you're onto something.

Source: Harry Dry (@marketing_examples) via David Perell. Full transcript: `source-transcript.md` (this folder).

## When to use

- Short, high-stakes lines: ad headlines, hero/landing lines, social + carousel copy, video VO, email subjects, taglines, CTAs.
- Choosing between candidate lines, or whenever a line feels generic.

**Not for:** long-form prose (articles, blog paragraphs) or legal copy - the test is built for short lines.

## The 3 rules

Run all three on each line:

1. **Can I visualize it?** Close your eyes - can you SEE it? Concrete and picture-able beats abstract. ("change an entire industry" - can't see it. "dads in Ohio at a barbecue in New Balance" - you see it.)
2. **Can I falsify it?** Can the claim be proved true or false? A checkable claim beats a vague aspiration - and it must actually BE true, because you're making a real promise.
3. **Can nobody else say this?** Is it bespoke to the brand, or could a competitor paste it verbatim? If a rival can run the same line unchanged, it isn't yours.

Pass all three = concrete, credible, ownable. Fail any one = generic.

## Workflow

1. **Grade** each line on the grid: visualize / falsify / ownable = ✅ or ❌. (Grading needs no extra facts - do it first.)
2. **Establish the facts** before rewriting any fail (see below) - you can't write a rule-2 line without something true to say.
3. **Rewrite** each ❌ line so it passes all three, then re-run the grid on the rewrite to confirm.
4. **Output** a table: `line | 👁 visualize | ✔ falsify | 🔒 ownable | verdict | rewrite`.

A line can fail as a **headline** but still work as a **proof point** (e.g. "trusted by thousands of customers"). When so, say it - demote to a support line, don't just delete.

## Establish the facts (so the falsify rule has ammo)

"Is it true / can I falsify it" means every rewrite makes a real, checkable promise - so it must be grounded in something true, never invented to sound good. Before rewriting, get the facts, in this order:

- **Use what's given** - pull concrete facts, numbers, mechanisms, and differentiators from the brief or conversation.
- **Read the source-of-truth** - if the project has product docs, a brand brief, or a positioning doc, or the user points you at a folder or site, read it first.
- **Ask the user** - if the truth is proprietary (only the owner knows it: how it works, pricing, guarantees, real numbers), stop and ask a short, batched set of fact-finding questions. One round, not an interrogation. It's fine to return the grid plus the questions and finish the rewrites after they answer.
- **Research** - if a claim is publicly checkable (an established brand, a category norm, a competitor's claim), use web search and cite what you find.

**Never fabricate a claim to pass "falsify."** If you can't ground a line, flag it as "needs a real proof point" and name the one fact that would unlock it - don't ship an invented claim or a bracketed `[placeholder]` as if it were finished copy.

*(If your org restricts which proof you may cite in customer copy - e.g. no internal-only stats, no unverifiable figures - follow those rules here too.)*

## Worked examples

**Fails all three** (a real recruitment ad): *"Don't just get a job. Change an entire industry."*
👁 ❌ can't picture "change an industry" · ✔ ❌ not a checkable claim · 🔒 ❌ any recruiter could write it → **cut.**

**Passes all three** (New Balance): *"Worn by supermodels in London and dads in Ohio."*
👁 ✅ you see both · ✔ ✅ verifiably true · 🔒 ✅ rivals can't claim it (dads in Ohio aren't in Prada; supermodels aren't in Reebok).

**Filler → concrete, once you have one fact** (a coffee subscription):
- ❌ *"Premium beans delivered to your door."* - "premium" is invisible and unprovable; every coffee box says it.
- ✅ *"Roasted Monday, at your door by Friday."* - you picture the gap, it's a checkable promise, and it's only true (and ownable) if they really roast-to-order. The unlock was one fact: roast-to-ship timing. No fact? Ask for it - don't invent a number.

## Common mistakes

- **Grading on vibes** ("feels generic") instead of running the three questions explicitly. Always show the per-rule ✅/❌ - that's the point.
- **Inventing a claim** to pass "ownable/visualize" that isn't actually true (fails falsify). Ground it, or flag it.
- **Shipping bracket-templates** ("Roasted `[day]`...") as if they were finished. A `[placeholder]` means you owe the user a question, not a deliverable.
- **Deleting a strong proof point** that was just a weak headline. Demote, don't delete.
- **Category filler** that fails "ownable" by default: "all-in-one," "powerful," "smarter," "seamless," "next-level," "premium," "reimagined," "elevate," "grows with you," "best-in-class." Treat as automatic ❌.
