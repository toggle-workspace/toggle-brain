# Client Log Template

This describes what to capture about each client. The Toggle Claude repo already keeps per-client docs, so use this as a guide for the kind of information to record there, adapting it to fit how the repo's client docs are already structured rather than imposing a rigid format.

The information falls into two parts:
1. **Durable facts** — the always-current snapshot of the client. Update in place when something changes.
2. **Monthly history** — one appended entry per report. Never overwrite past entries; always add new ones.

For a brand-new client with no existing doc, this template can serve as the starting structure for their doc.

---

## Template

```markdown
# Client Log: [Client Name]

## Durable facts (keep current)

- **Industry / type:** [e.g. B2C real estate / B2B Atlassian Marketplace partner]
- **Branding:** [Toggle or Meraaki]
- **Currency:** [RM / EUR / USD]
- **Platforms running:** [Meta, Google, TikTok, etc. — note what each is used for]
- **Primary goals:** [e.g. generate qualified leads, drive online sales, increase app evaluations]
- **Longer-term / business goals:** [e.g. expand to new market, grow enrolment, increase revenue X%]
- **Key contacts / approval process:** [if relevant, e.g. board approval needed, marketing manager is main contact]
- **Benchmarks:** [account averages worth remembering, e.g. average CPA range, target CPL, target ROAS]
- **What works:** [creative angles, audiences, keywords, campaign types that have proven effective]
- **What doesn't work:** [things tried that underperformed, to avoid repeating]
- **Client quirks / preferences:** [reporting preferences, tone, recurring questions, sensitivities]
- **Recurring growth observations:** [standing strategic notes beyond ads — e.g. landing page is weak, enrolment cycle peaks in Q3]

## Monthly history (append newest at the bottom)

### [Month Year] — reporting period [date range]

- **Platforms reported:** [list]
- **Headline results:** [key metrics per platform, e.g. Meta: 58 leads at RM24.39 CPL (-52% CPL MoM); Google: 33 conversions at RM29.05 CPA]
- **What drove performance:** [the main reasons behind the results]
- **What we recommended (Next Steps):** [the key actions proposed]
- **Growth observations raised:** [any beyond-ads insights surfaced this month]
- **Open questions / client actions requested:** [anything pending from the client]
- **To watch next month:** [things to follow up on, e.g. did the recommended keyword pauses improve CPA, is the new market generating conversions]

### [Next Month Year] — reporting period [date range]

- ...
```

---

## How to use the history when writing a new report

Before writing, read the full monthly history and look for:

- **Recommendations that were made but not yet evaluated** — the new report should close the loop ("following last month's recommendation to X, we observed Y")
- **Recurring patterns** — a trend visible across multiple months is more powerful than a single month's data point, and shows the client that Toggle is tracking their trajectory
- **Unresolved growth observations** — if a landing page or funnel issue was raised before and still persists, escalate it rather than repeating it quietly
- **Seasonality** — compare the same period across years if data exists, and anticipate upcoming seasonal shifts based on past entries

The goal is for each report to feel like a continuation of an ongoing strategic relationship, not a standalone monthly snapshot.
